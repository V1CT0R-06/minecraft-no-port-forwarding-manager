01

Understand the design

The panel is a small Flask application. Jinja produces HTML, one CSS file controls appearance, and a little browser JavaScript refreshes status and submits forms. There is no Node.js, database, Redis, frontend framework, or build process.

Player→Your DNS name→Playit→127.0.0.1:port→Docker→Minecraft

LAN and NetBird are for opening the private panel. Playit is for public Minecraft traffic. You do not need router port forwarding or a Cloudflare Tunnel.

02

Requirements

  • Ubuntu Server 22.04, 24.04, or another current Docker-supported Linux distribution
  • A 64-bit CPU, SSD storage, and preferably 8 GB RAM or more
  • A normal sudo-capable administrator account
  • Docker Engine and the Docker Compose plugin
  • Python 3 with venv, plus Git and curl
  • Optional: a Playit account and a DNS domain
Memory matters. Two modded servers can exhaust an 8 GB host. The panel reads real RAM at runtime and warns you, but it cannot create physical memory.
03

Install Docker

Use Docker's official Ubuntu repository, not a random installation script. The exact repository commands can change, so start with the official guide:

Docker Engine installation for Ubuntu

After the repository is configured, the packages are:

sudo apt update
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo docker run --rm hello-world
sudo docker compose version

Docker access is effectively root access. Do not expose the Docker socket over TCP and do not make it world-writable.

04

Install the panel

Put the code in a predictable location. Replace the repository placeholder after downloading or publishing your copy.

sudo apt install python3 python3-venv git curl acl
sudo useradd --system --home /nonexistent --shell /usr/sbin/nologin minecraft-panel
sudo git clone YOUR_REPOSITORY_URL /opt/minecraft-panel
cd /opt/minecraft-panel
sudo python3 -m venv .venv
sudo .venv/bin/pip install -r requirements.txt
sudo cp .env.example .env
sudo cp config/servers.example.json config/servers.json

A Python virtual environment keeps the panel's few Python packages separate from Ubuntu. It is disposable; application data does not belong inside .venv.

05

Configure secrets

Panel login

Generate a Flask session secret and a password hash. Never save the plaintext password in Git.

cd /opt/minecraft-panel
.venv/bin/python -c 'import secrets; print(secrets.token_hex(32))'
.venv/bin/python -c 'from getpass import getpass; from werkzeug.security import generate_password_hash; print(generate_password_hash(getpass("Panel password: ")))'

Edit /opt/minecraft-panel/.env and set:

PANEL_SECRET_KEY=paste-the-random-session-secret
PANEL_USERNAME=your-admin-name
PANEL_PASSWORD_HASH=paste-the-password-hash
PANEL_HOST=0.0.0.0
PANEL_PORT=8080
PANEL_TITLE=My Minecraft Homelab
PLAYIT_AGENT_NAME=my-server-hostname
MINECRAFT_DNS_ZONE=example.com
MINECRAFT_SERVER_ROOT=/srv/minecraft/servers
MINECRAFT_SHARED_ENV_FILE=/etc/minecraft-panel/minecraft.env

Minecraft RCON

Create a separate file used only by generated Minecraft Compose projects:

sudo install -d -m 0750 -o root -g minecraft-panel /etc/minecraft-panel
sudoedit /etc/minecraft-panel/minecraft.env

Put one strong random value inside:

RCON_PASSWORD=replace-with-a-long-random-secret

Then protect both files:

sudo chown root:minecraft-panel /opt/minecraft-panel/.env /etc/minecraft-panel/minecraft.env
sudo chmod 0640 /opt/minecraft-panel/.env /etc/minecraft-panel/minecraft.env

To change the panel password later, generate a new hash with the same command, replace only PANEL_PASSWORD_HASH, and restart minecraft-panel. Change the login name with PANEL_USERNAME.

06

Run the panel at boot

Create the restricted service account and writable server directory:

sudo install -d -o root -g minecraft-panel -m 0770 /srv/minecraft/servers
sudo setfacl -m u:minecraft-panel:rwx,d:u:minecraft-panel:rwx /opt/minecraft-panel/config

Install and adapt the example systemd unit. Check every path before starting it.

sudo cp deploy/minecraft-panel.service.example /etc/systemd/system/minecraft-panel.service
sudo systemctl daemon-reload
sudo systemctl enable --now minecraft-panel
sudo systemctl status minecraft-panel --no-pager
Security: membership in the Docker group is root-equivalent. Keep authentication enabled, use LAN/NetBird only, and never publish port 8080 directly to the Internet.
07

Import an existing server

Importing means adding metadata—not moving or recreating the server. First inspect it:

{% raw %}sudo docker inspect YOUR_CONTAINER
sudo docker inspect YOUR_CONTAINER --format '{{ json .Mounts }}'
sudo docker inspect YOUR_CONTAINER --format '{{ json .Config.Env }}'{% endraw %}

Copy config/servers.example.json to config/servers.json, then add an entry with its container name, Compose service/file, persistent data path, server type, and public hostname. Do not put RCON passwords or tokens in JSON.

If the Compose file lives outside the panel's normal writable directories, add only that exact file to ReadWritePaths and grant the service account a narrow ACL. This is needed only for RAM editing.

08

Create a Minecraft server

  1. Open Create server in the top navigation.
  2. Choose a simple lowercase ID such as creative.
  3. Select Vanilla, Paper, Fabric, Forge, or NeoForge.
  4. Enter a Minecraft version or use LATEST.
  5. Choose Java memory after reading the live host guidance.
  6. Enable the whitelist for a private friends-only server.
  7. Enter the desired public name, then review every path and resource value.
  8. Select Create. Watch Recent Logs until Minecraft says it is ready.

New worlds live under {{ server_root }}/SERVER/data. Their Compose file is beside the data directory, so the panel is never the only way to manage them.

09

Configure Playit

Install the official Linux package by following Playit's Linux guide. Claim the agent in your Playit account.

  1. Open the server's Network section.
  2. Confirm the displayed local endpoint says Listening.
  3. Open Playit Tunnels and create a Minecraft Java tunnel.
  4. Select your agent and copy the exact 127.0.0.1:PORT destination shown by the panel.
  5. Save the tunnel and copy its public endpoint back into the panel.

The panel guides this step because Playit does not publish a simple tunnel-creation API for this use. It never reads the private agent secret.

10

Configure your domain

After saving the Playit endpoint, the Network page generates exact CNAME and SRV records. Add those records at your DNS provider.

  • For Cloudflare, use DNS only (gray cloud).
  • Do not use Cloudflare Tunnel for Minecraft Java traffic.
  • Wait for DNS propagation, then refresh the Network page until it says Configured.

The panel performs read-only DNS queries. It never changes unrelated records.

11

Players, whitelist, console, and logs

Open a running server card:

  • Players online lists connected usernames.
  • Whitelist adds or removes valid Java usernames through RCON.
  • Minecraft Console sends only Minecraft commands. It is not a Linux shell.
  • Recent Logs fetches the latest Docker log lines without live streaming.

If these say unavailable while Docker status works, verify ENABLE_RCON=TRUE, the RCON secret, and container networking.

12

Change memory safely

Configured Java RAM is the maximum heap setting. Current container RAM is what Docker observes now. They are intentionally shown separately.

  1. Open Resources and enter a value such as 4G or 4096M.
  2. Read the projected heap total and recommended host reserve.
  3. Apply only when players can tolerate a restart.

The panel backs up the Compose text, updates its source of truth, and recreates only that container. The persistent /data mount is not deleted.

13

Back up worlds

Do not treat Docker or RAID as a backup. At minimum, create daily archives on a different disk and retain several generations.

  1. Use RCON save-off and save-all flush, or stop the server cleanly.
  2. Archive the server's persistent data directory.
  3. Re-enable saving with save-on if the server stayed running.
  4. Test restoring an archive into a separate directory.
This panel intentionally does not improvise live-world backups. Add a backup button only after your host backup script has been tested independently.
14

Update safely

Panel code

cd /opt/minecraft-panel
sudo git pull --ff-only
sudo .venv/bin/pip install -r requirements.txt
sudo .venv/bin/pytest
sudo systemctl restart minecraft-panel

Minecraft

Back up first. Read the server software's release notes and mod/plugin compatibility. Change one server at a time and inspect its logs. Never update a modded server merely because an image tag changed.

15

Troubleshooting

Panel will not start

sudo systemctl status minecraft-panel
sudo journalctl -u minecraft-panel -n 100

Docker unavailable

sudo systemctl status docker
sudo -u minecraft-panel id

Server will not start

sudo docker ps -a
sudo docker logs minecraft-SERVER --tail 100

Friends cannot connect

Check Minecraft locally, then the loopback port, Playit agent/tunnel, SRV record, and finally the public hostname—in that order.

16

Share it safely

Before publishing to GitHub or Reddit:

  • Run git status --ignored and confirm .env and config/servers.json are ignored.
  • Search the repository for domains, IP addresses, usernames, hashes, tokens, and RCON passwords.
  • Inspect Git history too. Removing a file in the latest commit does not erase it from older commits; publish a fresh sanitized repository if your development history contains private metadata.
  • Publish .env.example and config/servers.example.json, never your runtime files.
  • Explain that Docker-group access is root-equivalent.
  • Tell users to keep the panel private behind LAN, VPN, or NetBird.

The project deliberately stays small: Python modules for server logic, Jinja HTML templates, one understandable CSS file, and minimal vanilla JavaScript.
